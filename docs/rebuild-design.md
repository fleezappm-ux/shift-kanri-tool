# 作り直しの設計案（スプレッドシート版）

状態：案（2026-10-09）。決定済み：画面は配布元で公開（案1）。作業場所は rebuild/spreadsheet 枝。

## 目的
Notion・GitHubを使わずに、Googleアカウントだけで導入できるようにする。目標は導入15分前後（未測定）。

## 全体の形
- 保存先：Googleスプレッドシート1枚（雛形をコピーして使う）
- サーバー：そのスプレッドシートに同梱したGAS（コンテナバインド）。コピーするとコードも一緒に付いてくる
- 画面：配布元で公開（GitHub Pages）。各店は初回に自分のGASのURLを1回入れる（URL入りのリンクでも可）

## シート構成
| シート | 中身 | 今の置き場所 |
|---|---|---|
| シフト | 1行＝1人1日。従業員ID・日付・勤務・休憩・実働・備考・更新日時 | Notion「シフト管理DB」 |
| 休み希望 | 申請ID・従業員・日付・種類・コメント・状態・提出日時 | Notion「シフト希望届」 |
| 店舗 | 店舗名・店舗ID・各種の公開設定 | Notion「店舗設定DB」 |
| 設定 | 項目名と中身（JSON）。従業員・役職・勤務時間・特別日・人数ルールなど | Script Properties（約9KBの上限あり） |
| 記録 | エラー記録・操作記録 | Script Properties |
| ログイン | 操作員ごとのPIN（塩＋ハッシュ）。画面には出さない・保護する | Script Properties |

これで、従業員50人の上限と、保存の2段階化（Notionが遅いための仕組み）はなくせる見込み。

## 守ること（設計で決める）
1. 同時保存：LockServiceで順番に処理する（今のGASでも使っている）。
2. 見せる範囲：スプレッドシートは作った人（管理者）だけが開ける。従業員はアプリ経由だけ。共有しない旨を導入手順に書く。
3. 個人情報：ログインシートは「保護」し、手順書で触らないよう案内。
4. 速さ：開く・保存を試作で実測してから本作りへ。遅ければ設計を見直す。
5. 移行しないもの：Notionの既存データ。新規導入のみ。あおい薬局の本番には触らない。

## 進め方
1. この設計案にOK
2. 試作（シート3枚だけ：シフト・休み希望・設定）で、開く・保存の速さと導入手数を測る
3. 本作り（Notion部分をシートに置き換える。画面はほぼそのまま）
4. 導入手順書を短く書き直し、まっさらな状態から手順書どおりに通し確認
5. 実地確認（ユーザーと一緒に）

## 作業量の目安（Notionにふれている所）
GASのNotion呼び出しは、シフトの読み書き・休み希望の読み書き・店舗設定の3系統。ここを「シート読み書き」に置き換える。設定類はすでにJSONなので、保存先をシートに変えるだけ。

## 試作の測定結果（2026-10-09）
条件：50人×62日＝3,100行のシフトを入れたスプレッドシートを、GAS（単体プロジェクト）から読み書き。サーバー側の処理時間のみ（画面との通信・コールドスタートは未測定）。

| 処理 | 時間 |
|---|---|
| スプレッドシートを開く | 約0.23秒 |
| 3,100行を全部読む | 約0.35秒 |
| 1か月分（1,550行）に絞る | 0.001秒 |
| 1マス・31マスの書き込み | 約0.004秒（実際の確定は処理の終わりに行われる） |
| ロックの取得 | 約0.1秒 |
| キャッシュの書き読み | 約0.27秒 |

- 最初の素朴な作り（呼ぶたびにスプレッドシートを開き直す）は、読み込み約2〜2.5秒、保存約1.8〜2.8秒だった。**開き直しをやめて、1回開いて使い回す作りにすると、読み込みは約0.7秒まで下がる。**
- 結論：1回の通信で全部読める。Notionのように100件ずつ何回も問い合わせる必要がない。設計どおり進められる見込み。
- 未測定：Webアプリとしての往復（初回起動の遅さ）、同時に何人も保存したとき。本作りの段階で測る。

## 進捗（1つ目の区切り）
- GAS（`gas/Code.gs`）の保存先を Notion からスプレッドシートに置き換え済み。シフトは「シフト」シート、休み希望の控えは「休み希望」シートに自動作成。
- 反映待ち（裏書き込み）の仕組みは不要になり、保存と同時に反映。旧APIは互換のため空の応答を返す。
- 初期化は、スクリプトプロパティ `SHIFT_RESET_ALLOWED_SHEET_ID` にこのシートのIDを入れた控えだけ許可。
- 未着手：設定JSON（従業員など）のシート化（50人・9KB制限の解消）、休み希望の正本のシート化、導入手順書の短縮、実機での導入確認。

## 進捗（2つ目の区切り）
- 設定（従業員・勤務時間・お知らせ・休み希望・監査ログなど）を「設定」シートへ移動。ログイン合言葉・PIN・ログイン状態などの秘密は従来どおりスクリプトの設定（`isSecretShiftKey_`で振り分け）。
- 従業員50人の上限と、1値9KB・休み希望100件の上限を撤廃（300人・休み希望500件のテストあり）。
- 以前のスクリプト設定に残っているデータは自動で読め、次に保存するとシートへ移る（既存店の移行用）。
